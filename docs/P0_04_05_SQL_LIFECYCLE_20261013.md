## P0.05 browser regression and secure inventory loading — 2026-10-13

**RESOLVED on QA branch / TEST only:** The existing P0.05 browser form test previously failed two validations (negative unit cost and excessive discount) because inventory items had not loaded; diagnostics in [Actions #94](https://github.com/lucasmasseliamerica-cyber/masseli-business-manager/actions/runs/38406118596) showed `itemOptions=0`, `itemId=""`, and the earlier error "Add at least one item with a quantity greater than zero."

Read-only database inspection as simulated authenticated TEST OWNER B verified that `SELECT *` on `inventory_stock` and `inventory_transactions` was intentionally denied by column-level privilege restrictions, although the QA tenant possessed one item, one stock row and one transaction. Both existing stable SECURITY DEFINER read helpers `fn_read_inventory_stock_secure()` and `fn_read_inventory_transactions_secure()` are available to authenticated users (not anon), tenant-scoped and cost-redacted for roles without `manageRecipesAndCosts`. Broad SELECT grants would have been an unsafe fix.

**Applied QA-only frontend correction:** `useSupabaseInventory.reload()` now reads `rpc/fn_read_inventory_stock_secure` and `rpc/fn_read_inventory_transactions_secure` over PostgREST **GET**, preserving item filters and ledger sorting. Stable read-only functions support GET: https://postgrest.org/en/stable/references/transactions.html. No DB schema, privilege or RLS changes. An earlier fix in `NewPurchaseModal` also fills genuinely blank item IDs after async inventory loads, without overwriting existing user selections. Both `App.jsx` and `src/App.jsx` remain byte-identical. The QA workflow was updated to trigger on edits to root `App.jsx` as well.
